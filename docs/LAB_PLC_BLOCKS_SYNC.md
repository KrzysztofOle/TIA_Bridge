## Zakres dostępny

`plc-blocks-sync` ma kierunki `tia-to-repo`, `compare`, `repo-to-tia`, wybór nazw lub `*` i `--dry-run`. Publiczne `PlcBlock.Export` zapisuje niezmieniony SimaticML dla OB/FC/FB/GlobalDB/InstanceDB, z rekursją folderów. Manifest zawiera tożsamość, lokalizację, numer, język i SHA-256; porównanie chroni lokalne edycje, wykazuje zmiany, przeniesienia i zniknięcia względem baseline. Brak automatycznego usuwania bloków. Nazwy komponentów plików to odwracalne hex UTF-8; oryginalne nazwy pozostają w XML/manifeście.

Profil `v19-native-blocks/1-created-only` zachowuje whitespace i unknown fields; poza regułami składni XML ignoruje jedynie tekst bezatrybutowego, bez dzieci `/Document/DocumentInfo/Created`. ID, interfejsy, kod, namespace i pozostałe daty pozostają znaczące. Żaden przekształcony XML nie zastępuje oryginalnych bajtów. Diff jest pełnym tekstowym zastąpieniem XML, nie minimalnym diffem programu/AST.

Świeża tożsamość projektu/procesu/PLC, czysty projekt, mutex sesji, ExclusiveAccess, snapshot katalogu i niezależny powtórny eksport poprzedzają publikację. Staging i zachowany poprzedni katalog chronią pliki repo; nie stanowią backupu TIA. Przy tym samym modelu zachowuje się stare bajty/czasy eksportu; `NO_OP` nie publikuje plików. Manifest nie jest podpisanym produkcyjnym baseline/verification receipt. Po awarii publikacji wymagany jest przegląd staging/backup i publication.json; nie ma kwalifikacji power-loss ani automatycznego recovery.

## FC SCL — eksperymentalna kwalifikacja

Laboratoryjny adapter `LabPlcFcImport.cs` używa natywnego `PlcBlockComposition.Import`: None dla CREATE, Override dla UPDATE. Dopuszcza wyłącznie jedno root FC SCL `FC_LabExporter_SyncProbe` w dokładnym `X:\TESTY_TIA_Bridge\T05_RecipeSim_V19_Testowy\T05_RecipeSim_V19_Testowy.ap19`, z jawnym `--qualification-only`, zatwierdzonym hashem planu i zweryfikowanym backupem na X:. Interfejs skalarny, pojedynczy SCL i zamknięta gramatyka bez wywołań/globalnych zależności; zmiana interfejsu/metadanych lub kolizja blokuje UPDATE. Pozostałe rodzaje oraz ogólny import FC pozostają BLOCKED.

Plan wiąże dokładne pliki i manifesty, build/proces/projekt/PLC, cały chroniony inwentarz i tryb backupu. Backup korzysta z oficjalnego nieskompresowanego Archive(None) bez zmiany lokalizacji aktywnego projektu; wszystkie pliki i AP19 przechodzą hash readback. Import wymaga ponownego preflight pod ExclusiveAccess, trwałego intentu i zużycia planu, kwarantanny, Compile PLC bez błędów/ostrzeżeń, pełnej ochrony pozostałych bloków, Save/IsModified=False i niezależnego natywnego readbacku. Niepewność zatrzymuje zapisy bez retry/rollbacku; marker pozostaje po restarcie.

CREATE, UPDATE i odtworzenie po ręcznym usunięciu przez operatora mają osobne wyniki. Usunięcie oraz nowy CREATE restore wymagają zatrzymania testu i osobnych decyzji operatora. Na dokładnym testowym projekcie zatwierdzone CREATE, UPDATE i CREATE restore po ręcznym usunięciu probe uzyskały Import/Compile/Save/niezależny readback PASS; końcowe compare, repo-to-tia i tia-to-repo zwróciły NO_OP, zachowując hashe i mtime pakietu. Sześć negatywnych preflightów Engineering odrzucono przed zapisem. Restore ma własny backup, plan i zgodę; nazwa, numer, interfejs, język, kod i natywne metadane odpowiadają zachowanemu oryginałowi.
